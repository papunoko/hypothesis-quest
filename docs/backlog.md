## U — ウミガメ化（質問も仮説も受け、累積する）

2026-09-20 夜の決定: 遊びの形をウミガメのスープに寄せる。出題者の答えは検証済みの真相からコードが出す。Jev は入力がどの軸の話か・質問か主張かを読むだけ。
設計の骨子は [concept.md §12](concept.md)。

### 入力の受け方

2026-09-20実装: 質問／主張Choice・質問の話題Choiceと、題材2専用の比較データを追加。U-03は専用データのみ実装（共通化は未完）。U-05は本人が種別を選ぶフォールバックまでで、LLM分割は未実装。回答する問いを画面に明示し、未検証の問いは「まだ答えられません」と区別する。

- [x] **U-01** 種別判定: Choice {質問, 主張, どちらでもない} を `/api/read` に足し、鏡の先頭に「質問として読んでいます／仮説として読んでいます」を表示
- [x] **U-02** 質問への答え: はい／いいえ／場合による／関係ない。軸ごとの**最小対**（その軸だけが違う事例の対）から機械的に出す。「場合による」は対を2枚並べる（L5/L6）
- [ ] **U-03** 題材データに軸ごとの最小対を持たせる（T-60 の共通スキーマに1列追加）
- [x] **U-04** 主張への答えは従来どおり（反証カード／決まらない／一致）
- [ ] **U-05** 質問と主張が混ざった入力: Jev の {質問, 主張} が両方とも中間帯（例 0.35〜0.65）のときだけ LLM に渡し、**質問1文＋主張1文に書き直させる**。書き直した各文を Jev に読ませ直す。LLM は判定しない、分割するだけ。JSON を守らない応答は捨てて「どちらとして読めばいい？」の2ボタンに落とす

### 核心への近さ（採点にしない）

- [ ] **U-30** 「説明が通るテスト」: 最新の仮説が通る事例数を、帳面の横に **枚数ではなく段階**（まだ／半分／あと少し／全部）で出す。検証済み事実から計算。Jev を使わない
- [x] **U-31** 「核心に触れた」: 軸ごとに `core: true/false` を題材データに持ち、質問がその軸に触れたら相棒が「この質問は真相の中心に触れている」と一言。ウミガメの出題者の「いい質問です」に相当。個人の理解ではなく質問の性質への反応
- [ ] **U-32** 鏡の温度（任意）: 最新の読み取りベクトルと真相ベクトルの近さを「遠い／近づいた／かなり近い」の3段で。数値は出さない。ヒステリシスで揺れを抑える。**答えの方向を漏らす**ので、デフォルトはオフにして試遊で比べる
- [x] **U-33** 出さないもの: 軸の総数、理解度%、正答率。concept §2「明確に避けるもの」と同じ線

- [x] **U-12** 帳面パネル: 「調べたこと」を帳面から描く。確定事項（はい／いいえ）と「まだ聞いていない軸」を分けて出す。軸名は聞いた軸だけ表示（未入力の軸から答えを漏らさない）
