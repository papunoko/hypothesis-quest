# 独立監査 — 結果を見る前の基準

監査役: trial_auditor。会話履歴なし、計画のみを入力。以下は監査役の返答を整理したもの。

「バイアスを排した試遊」ではなく、**文脈漏洩と途中介入を抑えた、同一モデル2実行による探索的UI試験**と呼ぶ。contextの分離は共通の学習知識や推論傾向を分離しない。

| 格付け | 認定範囲 |
| --- | --- |
| 観測事実 | 操作と前後の画面で確認できる表示・遷移・エラー・重なり・結果 |
| 局所的な不一致 | 操作前の目標・期待と結果の食い違い。当該実行者についてのみ |
| UI不具合 | 可視UIが明示する動作/状態と実結果の矛盾、または必要な操作が表示上実行不能。足りなければ候補 |
| 解釈・仮説 | 誘導、混乱の原因、規則の理解、離脱理由。一般化・因果認定しない |

- 期待を支えた表現を「画面に明示」「画面から推測」「既有知識」「外部リンク」に分ける。自己申告で未申告の知識まで除去したとはしない。
- A/Bは端末比較ではない。経路/API応答/実行者などが交絡する。原因確認には同じ状態・操作を両幅で再現する。
- 外部リンク後の知識をアプリ内説明の効果にしない。
- API待機・エラー・応答差を読解や端末の差にしない。
- 上限での終了と自然離脱を分ける。未到達の画面は成功/失敗に数えない。
- 親の追試は「監査後の検証」として分離し、自然試遊を上書きしない。
- innerText/ariaSnapshotは視覚配置を迂回できる。そこで読めたことを「見つけやすい」とは扱わない。可能な限り引用の取得経路を残す。

残存バイアス: 同モデルの相関、専門知識、操作前後の言語化による慎重さ、課題への協力傾向、2実行という少なさ。発生率・一般ユーザーの理解・楽しさ・初心者の学習・端末の優劣は、この試験では言えない。
