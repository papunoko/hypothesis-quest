# ジャーニー案（試作）

## 0. 導入

プレイヤーはメンテナとして PR を読み、現状の振る舞いを一文で書く。書いたら事例が試す。
レビュワーの気持ちに立たせると仮説の向きが決まるので、プレイヤーは迷わず書き始める。

## 1. 軸の実測

| 仮説 | values | type | ms |
| --- | --- | --- | --- |
| 同じ引数で呼べば記憶を返す | 0.86 | 0.07 | 670 |
| 値が等しくても型が違えば別 | 0.05 | 0.97 | 224 |

読めていること: 意図した軸だけが立つ。遅延は 220〜750ms。

## 2. 鏡

入力欄の直下に、触れている条件だけが浮かぶバーを置く。デバウンス 400ms、閾値 0.20。
鏡があると「解釈の確認」が送信前に済み、プレイヤーは薄いバーを見て言い直す。

## 3. 山場

L5 と L6 を並べると「1 と 1.0 が同じか」が逆転する。ここで全員が引数の個数に気づき、面白さが最大になる。

## 4. 試遊メモ（2026-09-20、2人）

2人とも手3で L6 を見て 20 秒以上止まり、1人は「個数？」と口に出した。もう1人は鏡を見ずに送信した。
仮定: 鏡の位置が原因。次回は入力欄の直下に移して測る。
